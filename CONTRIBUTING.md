# Contributing to Bitloom

First of all, thank you for your interest in Bitloom! ❤️

Bitloom is currently developed primarily by a single maintainer, but contributions are welcome. Please read these guidelines before opening an issue or pull request.

## Before You Start

- Check existing issues and pull requests before creating a new one.
- If you plan to implement a large feature or make significant architectural changes, please open an issue first so we can discuss the design.
- Small fixes (bugs, documentation, typos, refactoring, tests) can be submitted directly as a pull request.

## Development

See the README for project setup and build instructions.

Before submitting a pull request, please ensure that:

- the project builds successfully;
- existing functionality is not broken;
- your changes follow the existing code style;
- commit history is clean.

## Pull Requests

Please keep pull requests focused on a single change.

A good pull request should include:

- a clear description of the change;
- the motivation behind it (if not obvious);
- any additional context if needed.

Large pull requests are harder to review and may take longer.

## Coding Style

Please follow the [Bitloom Style Guide](STYLE_GUIDE.md).

## Issues

Bug reports should include:

- Bitloom version;
- operating system;
- steps to reproduce;
- expected behavior;
- actual behavior;
- relevant logs if available.

Feature requests should explain:

- what problem they solve;
- why the feature would be useful.

## Licensing

By submitting a pull request, you agree that your contribution will be licensed under the MIT License.

## Questions

If you're unsure about something, feel free to open an issue before starting work.
